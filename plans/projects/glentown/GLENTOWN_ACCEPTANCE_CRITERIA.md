# GlenTown Acceptance Criteria

**Status:** CANONICAL / RELEASE-GATE BASELINE

GlenTown is release-ready only when the applicable implementation-plan checklist and these criteria are satisfied with evidence.

## Core criteria

- [ ] Canonical API ref has fresh full-suite and database verification.
- [ ] Canonical Flutter ref has fresh analyzer and test verification.
- [ ] Authentication and onboarding are verified on supported physical devices.
- [ ] Messaging is verified end-to-end for critical flows.
- [ ] Trip, Event and Financial Planner integrations pass regression verification.
- [ ] Core commerce and order boundaries are verified.
- [ ] Realistic seed/demo data is available with provenance and claimable-business semantics.
- [ ] Province Ready/readiness thresholds are evidenced for intended Beta availability.
- [ ] Responsive, accessibility and edge-case review is complete for release surfaces.
- [ ] Security, privacy and compliance review passes.
- [ ] Final physical-device visual audit passes.
- [ ] Production deployment verification passes for release surfaces.
- [ ] Implementation Plan and Memory reflect the verified release state.

Unchecked enhancement ideas do not block release unless they are explicitly designated as release-critical in the implementation plan.
