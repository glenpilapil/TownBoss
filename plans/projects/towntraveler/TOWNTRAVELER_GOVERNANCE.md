# TownTraveler Governance Baseline

Status: CANONICAL / PROJECT-SPECIFIC

TownTraveler inherits the TownBoss Development Rules and Project Governance Standard.

## Rules
- TownTraveler remains web-first and SEO-oriented.
- Shared GlenTown and TownBoss capabilities are reused through explicit contracts.
- Content and domain ownership must be decided before implementation.
- Guest-first browsing remains a product requirement.
- Nationwide content operations require provenance and quality controls.
- Material work updates the implementation dashboard and Memory.
- TownTraveler is Reference Implementation / Pilot #1 for `TOWNBOSS_SITES_PLATFORM`.
- TownBoss Sites may own generic site/page/theme/block/publishing concerns but must not absorb tourism-domain authority.
- TownTraveler public SEO, structured data, shareability and performance requirements cannot be weakened to satisfy builder abstraction.
- Dynamic site components should bind to authoritative domain providers instead of creating shadow copies of business data.
- Generalization follows evidence: extract now, contract now, extract later or keep vertical. Do not rewrite working vertical behavior solely for abstraction purity.
- TownBoss Sites plugins used by TownTraveler inherit the platform plugin permission, tenant-isolation, provenance, compatibility and lifecycle security requirements.

## Acceptance baseline
- [ ] Domain and content ownership contracts approved.
- [ ] TownBoss Sites core/plugin/vertical-extension boundary approved for the TownTraveler MVP.
- [ ] Public discovery quality criteria pass.
- [ ] Account and saved-travel flows verified.
- [ ] Trip Planner integration preserves shared orchestration boundaries.
- [ ] Shared-service integrations preserve authoritative ownership.
- [ ] Content operations include quality and provenance controls.
- [ ] Activated Sites extensions pass applicable security/permission review.

## Documentation compliance
Before substantial work, read the portfolio development rules, TownTraveler implementation plan, current state, this file, Memory, the TownBoss Sites architecture when applicable, relevant integration documents, and repository-local instructions. Re-check them when assumptions change. Final reports include a Documentation Compliance Receipt.
