# RealWise Governance Baseline

**Status:** CANONICAL / PROJECT-SPECIFIC

RealWise inherits `governance/DEVELOPMENT_RULES.md` and `governance/PROJECT_GOVERNANCE_STANDARD.md`.

## Project rules
- Do not rebuild GeoPlotter capabilities inside RealWise.
- RealWise owns brokerage operating workflows and RealWise-specific customer/agent/business rules.
- GeoPlotter remains authoritative for geospatial/project-inventory data and state.
- Shared TownBoss services are adopted only where semantics align and coupling is justified.
- Commercial structures such as rent-to-own, pasalo/assume-balance and brokerage payouts require explicit legal/compliance treatment before release.
- ERP scope expansion is prohibited unless separately approved.
- Material work must update the implementation dashboard and Memory.

## Acceptance baseline
- [ ] Operating roles/permissions and lead lifecycle are approved.
- [ ] CRM/routing/tripping workflows are verified.
- [ ] GeoPlotter inventory integration preserves source-of-truth ownership.
- [ ] Public marketing/content workflows are operational.
- [ ] Brokerage commission/payout rules have evidence-backed implementation where in scope.
- [ ] Compliance and privacy review passes for release scope.

## Documentation compliance
Before substantial work, read the TownBoss development rules, RealWise implementation plan, current state, this governance file, Memory, relevant GeoPlotter/TownBoss integration documentation and repository-local instructions. Re-check them when assumptions materially change. Final reports require a Documentation Compliance Receipt.
